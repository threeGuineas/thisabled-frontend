# AI 소통 코치(COMM) — 프론트엔드 연동 가이드

## 개요

- Base path: `/api/v1` → 전체 경로는 아래 5개 엔드포인트
- 인증: `Authorization: Bearer <access_token>` 필수 (모든 엔드포인트 공통)
- 노출 범위: 전 UI 모드(시각·청각·발달·기본)에서 사용 가능. **발달 모드에서는 기본 노출**, 다른 모드에서는 해당 화면의 보조 기능으로 접근 (`docs/ThisAbled_기능명세서_v2_2.md` §COMM 개요)
- 모든 기능 **버튼을 직접 눌렀을 때만** 호출해야 함 — 자동 분석/자동 호출 금지 (COMM-05)

| 기능 | 엔드포인트 | 상태 |
|---|---|---|
| COMM-01 쉬운 문장 변환 | `POST /api/v1/comm/simplify` | 구현 완료 |
| COMM-02 문장 완성 | `POST /api/v1/comm/complete` | 구현 완료 |
| COMM-03 채팅 답장 추천 | `POST /api/v1/comm/replies` | 구현 완료 (1:1 채팅방 한정) |
| COMM-03 게시물 댓글 추천 | `POST /api/v1/comm/comments` | 구현 완료 (아래 참고 — 백엔드에 별도 엔드포인트로 추가됨) |
| COMM-04 대화 힌트 | `POST /api/v1/comm/hints` | 구현 완료 |

> 2026-08-15 업데이트: 아래 §3은 게시물 댓글 추천 API가 없다고 안내했었지만, 백엔드 `/api/v1/openapi.json` 기준 `POST /api/v1/comm/comments` 엔드포인트가 별도로 추가되어 현재는 구현되어 있음. 프론트 `getCommentSuggestions()`(`src/services/comm.ts`)가 이를 사용하며, 발달모드 게시물 상세 화면(`DevPostDetailScreen.tsx`)의 "댓글 추천 받기" 버튼에 연결되어 있다.

## 1. 쉬운 문장 변환 — `POST /api/v1/comm/simplify` (COMM-01)

긴 게시물/복잡한 문장을 쉬운 문장으로 바꿔준다.

**Request**
```json
{ "text": "string (1~2000자)" }
```

**Response 200**
```json
{
  "result": "쉬운 문장으로 변환된 결과",
  "original": "원문 그대로"
}
```

- `original`은 요청으로 보낸 `text`를 그대로 되돌려주는 값. **프론트가 직접 원문을 들고 있지 않아도** 응답의 `original` ↔ `result` 두 값을 그대로 전환 토글에 쓸 수 있음.
- 명세(COMM-01)상 "AI 변환 결과임을 표시"해야 하므로, `result`를 보여줄 때 AI 생성 표시(배지/라벨 등)를 UI에 반드시 넣을 것.
- `text`가 빈 문자열이거나 2000자를 초과하면 422 (Pydantic validation error).

## 2. 문장 완성 — `POST /api/v1/comm/complete` (COMM-02)

쓰다 만 문장의 완성본 후보를 제안한다.

**Request**
```json
{ "text": "string (1~2000자, 쓰다 만 문장)" }
```

**Response 200**
```json
{ "suggestions": ["완성본 후보 1", "완성본 후보 2"] }
```

- 후보 개수는 **고정되어 있지 않음** (LLM 프롬프트는 2개를 요청하지만 JSON 파싱 실패 시 줄 단위로 최대 3개까지 나올 수 있음). 프론트는 `suggestions.length`에 유동적으로 대응해야 함.
- **중요 (정책, §20-8): 서버는 절대 자동으로 입력창에 채우거나 게시하지 않는다.** 프론트도 동일한 원칙을 지켜야 함 — 사용자가 후보 중 하나를 선택하면 입력창에 채워 넣기만 하고, 사용자가 최종 확인 후 직접 전송/게시하도록 UX를 구성할 것. 후보 선택 즉시 자동 전송하는 흐름은 만들면 안 됨.

## 3. 채팅 답장 추천 — `POST /api/v1/comm/replies` (COMM-03, 채팅방 한정)

**Request**
```json
{ "room_id": "uuid" }
```

**Response 200**
```json
{ "suggestions": ["답장 후보 1", "답장 후보 2", "답장 후보 3"] }
```

**Response 404**
- `room_id`에 해당하는 채팅방이 없거나, **요청자가 그 채팅방의 참여자가 아닌 경우** 404 반환 (`{"detail": "채팅방을 찾을 수 없습니다"}`).
- 프론트는 채팅방 화면(참여자 컨텍스트) 안에서만 이 기능을 노출하면 되므로 정상 플로우에서는 404를 만날 일이 거의 없지만, 방어적으로 에러 핸들링은 넣을 것.

**동작 방식 (COMM-05 데이터 처리 원칙 — 알아두면 좋은 것)**
- 서버가 해당 채팅방의 **최근 10개 텍스트 메시지**만 컨텍스트로 사용해 LLM에 보낸다 (전체 대화 기록을 보내지 않음).
- 신고(flagged)되었지만 아직 열람되지 않은 메시지는 컨텍스트에서 자동 제외된다. 프론트가 별도로 필터링할 필요 없음.
- 텍스트 타입 메시지만 컨텍스트에 포함됨 (이미지 등 비텍스트 메시지는 제외).
- 후보를 선택하면 **전송 전에 입력창에서 확인·수정할 수 있어야 한다** (명세 COMM-03). 즉 선택 즉시 자동 전송 금지 — COMM-02와 동일한 원칙.

## 3-1. 게시물 댓글 추천 — `POST /api/v1/comm/comments` (COMM-03, 게시물 한정)

게시물 본문과 최근 댓글을 컨텍스트로 사용해 평문 댓글 후보를 제안한다. `/replies`(채팅방)와는 별도 엔드포인트.

**Request**
```json
{ "post_id": "uuid" }
```

**Response 200**
```json
{ "suggestions": ["댓글 후보 1", "댓글 후보 2"] }
```

**Response 404** — `post_id`에 해당하는 게시물이 없거나, 비공개/차단 관계 등으로 열람할 수 없는 경우.

**Response 503** — AI 소통 코치 일시 불가.

- 후보를 선택하면 입력창에만 채우고, 사용자가 확인 후 직접 댓글을 등록해야 한다 (자동 게시 금지 — COMM-02/COMM-03 채팅 답장과 동일 원칙).
- 프론트 구현: `getCommentSuggestions()` (`src/services/comm.ts`), 발달모드 게시물 상세 화면(`DevPostDetailScreen.tsx`)의 "댓글 추천 받기" 버튼.

## 4. 대화 힌트 — `POST /api/v1/comm/hints` (COMM-04)

현재 채팅방 대화 맥락을 바탕으로 인사/질문/거절 등 소통 힌트를 제공한다.

**Request**
```json
{ "room_id": "uuid" }
```

**Response 200**
```json
{ "hints": ["인사로 시작해 보세요", "궁금한 점을 물어보세요", "부담되면 거절해도 괜찮아요"] }
```

**Response 404** — `/replies`와 동일 (채팅방 없음 / 비참여자).

- 컨텍스트 조회 방식은 `/replies`와 동일 (최근 10개 텍스트, flagged 미열람 제외, 참여자만 호출 가능).
- 명세(COMM-04)상 이 힌트는 **"상대방의 의도나 감정을 사실로 단정하지 않는다"**는 원칙으로 생성됨. 프론트 문구/톤도 이를 해치지 않도록 "~일 수 있어요", "~해 보세요" 같은 제안형 UI로 노출할 것 (단정형 문구로 재가공하지 말 것).
- 명세상 "코칭 레벨"이나 "사용자 등급" 같은 게이미피케이션 요소는 제공하지 않음 — 힌트에 점수/레벨을 붙이는 UI를 만들지 말 것.

## 공통 — 외부 API 전송 고지

5개 기능 모두 내부적으로 외부 LLM(OpenAI)에 텍스트를 전송해 처리한다 (§17.2 고지 대상). 프론트는 이 기능을 처음 사용하는 시점(또는 온보딩)에 "입력한 문장/대화 내용 일부가 AI 서비스로 전송되어 처리됩니다"와 같은 고지를 사용자에게 노출해야 한다.

## 에러 공통 사항

- 인증 실패: 401
- `text`/`room_id`/`post_id` 형식 오류: 422
- 채팅방 관련 2개 엔드포인트(`/replies`, `/hints`)의 404는 위 설명 참고
- `/comments`의 404는 게시물이 없거나 열람 불가한 경우 (§3-1 참고), 503은 AI 소통 코치 일시 불가
- 그 외 서버/LLM 호출 오류에 대한 별도 커스텀 에러 포맷은 없음 (500 그대로 전파). LLM 응답이 JSON 파싱에 실패해도 500이 아니라 줄 단위로 파싱한 결과(최대 3개)를 200으로 반환하므로, 프론트에서 별도 재시도 로직을 넣을 필요는 없음.
